# Laboratory 02 – Build the Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focused on understanding and investigating the basic components of cloud infrastructure. I used the KillerCoda Linux environment to examine compute, storage, networking, and operating system resources. I also compared infrastructure services from AWS, Microsoft Azure, and Google Cloud and created a simple cloud infrastructure diagram.

## Objectives

* Explain the major components of cloud infrastructure.
* Investigate hardware and software resources in a Linux environment.
* Identify compute, storage, networking, and operating system resources.
* Compare equivalent infrastructure services from AWS, Microsoft Azure, and Google Cloud.
* Create a simple cloud infrastructure diagram.
* Practice technical documentation using Markdown.
* Improve my GitHub Cloud Computing Portfolio.

## Cloud Infrastructure Components

The main cloud infrastructure components investigated in this laboratory were:

* **Compute:** CPU and RAM used to process tasks and run applications.
* **Storage:** Disk space used to store the operating system, applications, and data.
* **Networking:** Network interfaces and IP addresses used for communication.
* **Operating System:** Ubuntu-based Linux environment used to manage the server resources.
* **Identity and Access Management:** Services used by cloud providers to control access to cloud resources.

## Linux Commands Executed

The following Linux commands were used to investigate the cloud server:

```bash
cat /etc/os-release
uname -r
lscpu
nproc
free -h
df -h
findmnt
hostname
hostname -I
```

These commands were used to identify the operating system, kernel version, CPU, CPU cores, RAM, disk storage, mounted filesystems, hostname, and IP addresses.

## Skills Learned

During this laboratory activity, I learned how to inspect and analyze a Linux-based cloud environment using basic terminal commands. I also learned how to identify the different components of cloud infrastructure and compare equivalent services between AWS, Microsoft Azure, and Google Cloud. ## Challenges Encountered

One challenge I encountered was understanding the information displayed by the Linux commands because some commands returned technical details that were unfamiliar to me. Another challenge was comparing cloud provider services because AWS, Azure, and Google Cloud use different names for services that perform similar functions. Creating the cloud infrastructure diagram was also a learning experience because I had to understand how the different components connect with each other.
