# Mission 2 Reflection

This laboratory activity helped me understand the basic components of cloud infrastructure and how they work together. For me, compute resources are one of the most important components because they provide the processing power needed to run applications and services. The CPU and RAM allow a server to process commands and perform different tasks. Without enough computing resources, applications may become slow or may not work properly.

I also learned how Linux supports cloud computing. By using the KillerCoda Linux environment, I was able to use different commands to check the CPU, RAM, storage, network information, hostname, and kernel version of the server. This helped me understand how cloud engineers can use the Linux terminal to inspect and manage server resources.

Another important lesson I learned is the importance of technical documentation before deploying infrastructure. Documentation provides a clear record of the resources, configurations, and decisions made during the planning process. It can also help engineers troubleshoot problems and allow other team members to understand how the infrastructure is organized.

During this laboratory, I developed new skills in using Linux commands, identifying cloud infrastructure components, and comparing similar services from AWS, Microsoft Azure, and Google Cloud. I also learned how to create a simple cloud infrastructure diagram and organize technical information using Markdown and GitHub.

Lastly, this mission improved my GitHub portfolio because I added infrastructure documentation, cloud provider comparisons, screenshots, and a cloud architecture diagram. I realized that GitHub is not only useful for storing code but can also be used to document projects and show the skills I have learned. Overall, this activity gave me a better understanding of how cloud infrastructure works and how important planning and documentation are before deploying a cloud system.
